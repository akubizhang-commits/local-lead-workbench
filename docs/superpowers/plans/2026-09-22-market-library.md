# 目标市场企业库实施计划

Goal: 用户按城市和目标类型维护长期企业库，无企业数量输入。每轮自动检索、去重、更新，并区分本市场新增、存量与变化。
Architecture: tasks 作为市场定义；market_memberships 保存企业市场归属，run_companies 保存逐轮相遇及变化；持久化 work_items 存放城市检索及可细分地理网格，官网复核在发现阶段后处理。旧企业、来源及人工修改保留。

- [x] 城市查询规划和 Maps 地理参数：城市边界框缓存、关键词扩展、稳定网格键、密集结果自适应细分；内部预算停止时明确未完成，不宣称城市全量。
- [x] 数据库迁移：市场归属、轮次新增/存量/变化、不再命中；同来源不重复，强身份证据保守去重；已有值变化自动更新，人工覆盖保留审核。
- [x] 后台流程：规划、发现优先、所有结果增量入库，检查点及继续；已有市场重复创建复用，重新运行整轮并安全合并。
- [x] API/导出：移除用户数量限额，市场统计与分页列表、轮次筛选，导出匹配市场全量而非当前页。
- [x] 界面：目标市场卡片、维护市场按钮、新增/存量/变化计数、市场企业分页和筛选；删除数量上限及“找到目标数”文案。
- [x] 自动化验证：重复运行不增重复、城市隔离、变化分类、人工修改保护、超500条分页和导出、规划细分/失败可恢复、迁移保留旧数据。
- [x] 浏览器验证与小规模真实验证；避免自动对全部已有市场启动长时间采集。

边界：新增指本轮首次进入该市场；存量指该市场历史已有且本轮再次发现；资料变化是本轮发现或官网观察与既有值不同的企业子集。未再次发现不删除。候选与已核实分开展示，检索命中不是业务或行政边界证明。公开源有可见性限制，界面仅声明实际已检索范围。

## 已确认实施约定

- 市场定义复用 tasks；数据库版本升级为 2，market_memberships 与 run_companies 持久化归属和分类。
- /api/company-page 提供分页；/api/exports 接受相同市场、轮次、分类过滤，忽略页码导出全部结果。
- 新 API 忽略旧客户端传入的企业数量参数，市场本身不设企业总数截断。内部每个检索单元最多收集120条、180秒；密集结果细分，未完成时保持partial。
- 城市参考范围优先使用缓存的城市级定位；本机 Nominatim 公共接口实测超时，根查询回退需明确显示，不声称覆盖城市网格。没有静默采用未经验证的范围。
