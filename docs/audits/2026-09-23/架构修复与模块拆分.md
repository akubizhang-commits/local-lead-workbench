# 架构修复与模块拆分

对应《系统架构与代码结构评审》的前三项问题，以及相关模块拆分和测试完善。

## 已实现的行为

| 问题 | 修复后 |
|---|---|
| 不同社媒操作误复用任务 | 企业集合、操作类型、读取配置和搜索配置相同才复用活动任务；资料补充、账号读取和站内搜索分别排队 |
| 成功但字段缺失的更新隐藏旧资料 | 每种字段使用最近一次非空成功观察；保留字段来源与实际采集时间 |
| 新旧字段冲突无法追溯 | 当前字段与此前不同值分开；账号详情可展开历史值及原始证据，历史值不冒充当前值 |
| 失败响应污染资料 | 登录页、失败响应的内容不进入有效字段；保留旧资料，同时继续显示本次失败状态 |
| 市场运行阻塞社媒 | 市场和官网运行按工作项轮转，每轮处理一个社媒工作项；新加入和恢复的市场排在轮转队列末尾 |
| 缓存复用更新了“采集时间” | 共享账号复用只推进工作项，不新增账号观察；历史缓存副本不参与有效来源时间计算 |

调度切换发生在工作项之间，不能立即打断正在执行的单个网络读取。暂停、取消、进程停止和恢复仍保留原有语义；停止官网任务时会等待子协程清理资源。

账号资料投影是只读计算，没有删除历史快照。当前字段缺失并不代表旧字段已失效；此改动没有新增自动判定邮箱失效的能力。

## 模块职责

后端：

- `social_run_policy.py`：定义社媒任务执行语义和去重依据。
- `social_projection.py`：计算账号当前字段、字段历史和各自来源时间，不访问数据库或网络。
- `worker_scheduler.py`：工作项公平轮转。
- `work_item_executor.py`：执行规划、发现、官网工作项。
- `worker.py`：保留进程生命周期、锁、心跳和兼容批量入口。
- `social_discovery_store.py`：保留持久化和任务状态，调用独立规则与投影模块。

前端：

- `pages/`：拆出市场、企业列表、企业详情、审核、更新记录和设置页面。
- `social/`：拆出联系人/账号列表、详情、字段来源、帖子、归属决定和跟进。
- `App.tsx`：应用布局、路由和共享操作。
- `SocialPanel.tsx`：社媒数据与操作协调，保留原组件导出兼容。
- `tests/support/`：共用 TSX 加载与 DOM 测试环境。

本次没有全面替换 Store 的其他存储职责，也没有引入微服务、分布式队列或新数据库。

## 测试覆盖

后端新增：

- 不同操作独立建任务、同操作复用、配置变化、企业顺序不影响去重。
- 空字段、部分字段、失败后的资料保留、旧值历史与时间。
- HTTP 接口返回的任务和字段来源契约。
- 投影不改写观察证据、共享账号缓存不伪造新时间、历史缓存兼容。
- 多市场与社媒交替执行、新任务与恢复任务加入队列。
- 暂停、取消、来源异常、进程恢复和资源释放。

前端：

- 固定 `jsdom@26.1.0` 为开发依赖，三项 DOM 测试默认执行。
- 路由返回保留列表筛选与页码、翻页清空选择。
- 批量修改冲突不会悄悄重试。
- 账号归属决定、跟进草稿与字段来源时间。
- 修复测试暴露的缺失会话状态处理与重复 React key。

## 本地数据与页面验证

最终自动验证：后端 **468 passed、44 subtests passed**（2 条依赖弃用警告）；前端 **50 passed、0 skipped**；TypeScript 检查和 Vite 构建通过。

只读检查现有 294 个账号、602 条观察快照。识别出 22 条历史缓存副本；这些记录仍保留，但不会再被当作新的采集证据。投影后的 463 个字段均带有观察时间。此检查验证数据处理兼容性，不代表逐一核实字段真实有效。

实际页面验证：企业详情 → 联系人详情 → 返回；企业详情 → Instagram 账号详情；设置页加载与后台在线状态。账号详情展示字段采集日期和来源。测试没有启动真实平台抓取或发送消息。

性能评审中的历史快照索引、帖子分页和持久化当前资料投影，仍属于后续优化，未混入本轮前三项修复。
