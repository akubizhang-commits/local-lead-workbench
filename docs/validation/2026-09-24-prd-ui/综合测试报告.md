| 问题 | 修复与验证 |
|---|---|
| 任务页返回、操作、筛选分散；查看详情可能被横向挤出 | 返回置于标题上方；市场操作在概览标题右侧；筛选集中；来源合并企业列，操作固定最后一列。轮次详情改原生对话框。 |
| 复核详情返回丢失筛选/轮次上下文 | 路由保存进入前上下文；回归验证分页、状态、轮次；浏览器实测11条失败记录，返回仍为failed筛选。 |
| 改国家仍提交旧州/城市 | 地域受控输入，上级变化清空下级；DOM回归通过。 |

| 手工回复记录看起来像平台回执 | 历史统一带“人工记录”来源；回归通过。 |

企业列表未选择记录时隐藏批量工具栏，统计定义改可展开说明。账号详情移除企业编辑/官网复核等非当前对象操作。低对比说明文字加深。文档已同步实现变化。

## 浏览器实测记录与限制

- 市场列表、市场复核列表、复核详情、企业库、企业详情、Instagram账号详情、待审核、更新记录、设置均能加载，无页面错误提示。设置包含来源、社媒发现、连接、定时与备份六个区块。
- 任务选择“失败”得到11条均为失败的记录；打开Urth Apparel详情能够看到企业名称、失败原因及所属整轮控制；返回保留筛选及11条结果。
- 企业列表显示50条，未选择时无批量操作栏；Mure + Grand门店详情有联系人/账号列表，进入Instagram详情后只显示账号相关内容。
- “查看轮次”打开原生dialog，初始焦点在关闭按钮；Escape关闭。没有点击“继续”或触发真实爬取。
- 浏览器原有缩放影响viewport换算。实际测量CSS视口宽1028、731、548；文档宽分别不超过视口，731时任务表容器约597px、overflow-x:auto；验证的是窄屏重排，不宣称完成100%缩放下精确1440/1024或200%缩放全站验收。覆盖截图及默认界面目视检查，未做全站WCAG审计/屏幕阅读器验收。
- 真实浏览器只读；写入、冲突、拒绝联系、备份恢复、暂停恢复、导出等用临时库/API或DOM替身测试，不改客户实际审核决定，不发送邮件/社媒消息。

## 尚未完成与后续优先级

自动化通过表示已测实现符合对应断言，不能代表全部PRD通过。

| 优先级 | 剩余问题/能力 | 影响与下一步 |
|---|---|---|
| P2 | 审核的业务类型仍直接显示JSON数组；资料变化仍显示长JSON | 浏览器发现，可读性不足。下一步做按字段中文展示与差异摘要，保留原始证据展开。 |
| P2 | 完整导航/刷新后的持久化可编辑草稿尚未实现 | 本轮只保证同窗口页面切换保留；需要完整草稿存储、恢复及跨路由提示协议。 |
| P2 | 全站200%缩放、键盘遍历、HTTP404专属状态及大规模性能验收未完成 | 需要补专门可访问性、异常页和容量测试；现有窄屏/通用错误测试不能替代。 |
| 计划能力 | PRD-01完整产品/目标客户配置，严格行政区核验，人员与渠道统一身份模型 | 当前实现部分；详情见后端矩阵，不能作为已验收交付项。 |
| 计划能力 | PRD-08统一邮件/社媒草稿、PRD-09真实发送/幂等/未知结果对账、PRD-10回复同步 | 当前没有完整发送闭环；本轮没有实际投递。 |
| 计划能力 | 完整联系人/社媒与跟进历史导出 | 当前已测企业CSV/XLSX不等于这一完整交付格式。 |
| 外部待验证 | Maps真实召回、Facebook/Instagram/X登录后的持续读取、采购身份准确率 | 本轮使用替身验证解析/重试/状态，不声称平台稳定抓取或全城100%覆盖。 |

建议交付判断：可以继续内部试用当前发现、资料维护和人工跟进功能；完整商业获客闭环仍需完成上述计划能力及真实平台验收。
