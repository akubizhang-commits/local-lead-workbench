# 社媒组合采集：试用说明与验证结果

日期：2026-09-22

## 已接入

- Instagram / Facebook 专用浏览器配置目录、人工登录窗口、关闭与释放会话。
- 浏览器方式读取实际加载的简介和有限近期帖子。默认每次最多 3 条，可设置 1–5 条；不保证获取全部帖子。
- Instagram 可切换 Instaloader 对照读取。该适配器读取公开资料，不复用浏览器 Cookie，不代填密码，不自动处理验证。
- YouTube API 可选配置，支持频道 ID、@handle 和 user 形式的频道主页。读取频道简介和上传列表中的有限近期视频；未配置密钥时保持原 HTTP 读取路径。
- 本机 HTTP / SOCKS5 代理可配置。浏览器支持两种方式；Instaloader 和当前 YouTube 适配器使用 HTTP 代理，选择 SOCKS5 会提示改用 HTTP 端口。
- 企业详情新增“读取已有账号与近期帖子”，跳过官网与搜索阶段。原有“开始单企发现”和 20 家试点保留。
- 采集帖子按 URL 去重关联；正文、发布时间（来源提供时）及原始链接展示在企业详情。没有明确人员归属的邮箱/电话只保留为候选字段。
- 原有取消、重试、历史保留和拒绝联系保护继续生效。部分简介成功但帖子失败的运行标记为部分完成。
- 修复恢复备份遗漏活动社媒任务检查的问题。

## 如何试用

1. 打开本地应用的“设置 → 社媒读取连接”。正式环境已预设浏览器方式，每次最多 3 条帖子。
2. 点击“打开 Instagram 登录浏览器”或 Facebook 对应按钮，在独立窗口手动登录。
3. 回到设置，点击“关闭并释放 … 会话”。关闭会保留专用配置目录，供后台复用；窗口状态不代表认证已经验证。
4. 在企业库选择已有社媒账号的企业，进入详情，点击“读取已有账号与近期帖子”。
5. 等运行结束，点击页面顶部“刷新数据”，查看简介、帖子、候选字段和来源。需要搜索新账号时才使用“开始单企发现”。
6. Instagram 对照试验：回设置选择 Instaloader、保存，然后在同一企业重新运行读取。它可能因公开访问限制而失败；以逐项报告为准。
7. YouTube：在设置输入自己的 API key、保存，再读取已关联的 YouTube 频道。留空不修改已有密钥，勾选清除才删除。

若专用浏览器打不开平台页面，先确认本机网络是否可访问，必要时填写本机代理并重新打开窗口。配置代理不会自动改写 SearxNG 的上游代理；已有账号读取不依赖 SearxNG。

## 本地保存与进程

- 非敏感读取配置：`data/social-connections.json`。
- API 密钥：`data/social-secrets.json`，文件权限 0600；不回填界面、不进入运行快照。
- 专用会话：`data/social-browser/instagram`、`facebook`，目录权限 0700。
- 登录窗口与 Worker 用同一配置目录的文件锁，避免并发占用。
- 正常停止 API 会关闭由其打开的登录窗口。
- SQLite 备份保存业务资料，不打包浏览器会话及 API 密钥。恢复业务数据库不会替换上述连接配置文件。
- 新机器可执行 `bash scripts/install_social.sh` 安装可选依赖；优先使用已安装的 Chrome，否则安装 Playwright Chromium。

| 浏览器真实 Instagram 抽测 | 读取到 `shop.storia` 公开标题和简介，0 帖子、0 联系字段 |

真实抽测没有登录账号，没有发送消息，也没有将隔离数据写入正式企业库。`browser-public-probe.json` 是当次真实结果；当次将简介成功记录为 succeeded，随后补充了“只读到简介、未读取到帖子”时的 partial 标记，避免把简介成功误解为帖子采集成功。

本次没有拿到用户登录后的帖子样本，也没有使用真实 YouTube 密钥。Instaloader / YouTube 的解析、错误分类、限额和超时通过模拟边界测试验证，真实账号覆盖率尚待试用。不能据此承诺所有平台和账号可读。
