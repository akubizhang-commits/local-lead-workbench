这四份文档以用户本轮明确的目标为准：

> 企业用户用于获客：从 Google Maps 按关键词发现指定海外城市的相关企业，通过官网和 Facebook、Instagram、Twitter（X）寻找采购或关键员工的联系方式，再向指定入口发送产品介绍邮件或社媒消息。

这是产品目标，不是当前功能已经全部具备的声明。本轮整理文档与评审，没有实现发送能力，也没有发送消息。

2026-09-25：PRD-04、IX-02 和 UI-04 已同步市场社媒集成：企业发现后官网/社媒并行、平台独立等待、未来设置与轮次快照、已有市场显式补充。最终回归与本地部署验收完成，测试及数据保留记录见[实施审计](../validation/2026-09-25-market-social-integration.md)，实现细节见[技术设计](../technical/market-social-integration.md)。这次更新不开放发送能力，也不自动回放历史市场。

## 文档状态

| 标记 | 含义 |
|---|---|

## 现有文档核对

项目原来有 [requirements.md](../requirements.md)，具备 PRD 的主要内容，并非没有需求文档。但它是 2026-09-22 的早期稿，仍包含“尚未实现”“最多100家”和“不做发送”等旧范围，与当前代码及本轮目标有冲突。

[technical-design.md](../technical-design.md) 同样是早期技术建议，不是准确的现行架构说明。现行架构、拓扑和接口以 [技术文档总览](../technical/README.md) 为准；历史分析参考 [系统架构评审](../audits/2026-09-23/系统架构与代码结构评审.md) 与 [已完成修复记录](../audits/2026-09-23/架构修复与模块拆分.md)。

本目录是新产品目标、交互和 UI 的评审基线；旧文档保留用于追溯。未来实施时需记录所采用的需求编号及版本，并同步更新“当前实现”列。

## 核对证据

- 需求输入：用户本轮目标及此前关于全市场累积、去重、采购优先、统一联系人列表、来源和社媒帖子展示的说明。
- 源码：`leadworkbench/`、`frontend/src/`；具体依据见交叉评审。
- 页面体验：本轮只读查看企业库截图、页面入口与筛选；其他页面结合当前源码和前轮实际页面验证。
- 历史验证：前轮后端 468 项、前端 50 项测试通过。这是自动测试基线，不是本轮重新全测，也不是城市召回率、人员准确率或发送成功率证据。
- 两个独立评审视角：产品/后端能力核对、前端交互/UI 核对；新版文档随后进行交叉核对。

没有外部用户访谈数据、真实发送实验或转化率数据；文档中的业务效果指标均为建议验证方法。
