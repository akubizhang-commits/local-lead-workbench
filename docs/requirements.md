## 1. 产品目标

让内部销售人员按“国家 → 州／省等行政区 → 城市＋业务关键词”发现企业，整理可追溯的企业资料，寻找公开的采购联系人和工作邮箱，并通过手动或定时任务复核资料。

产品输出是一份可审核、可更新的销售候选名单，不承诺覆盖区域内全部企业，不把公开邮箱直接等同于有效采购线索。

### 1.1 已确认需求

| 编号 | 需求 |

| C02 | Google Maps 是用户指定的企业发现入口 |
| C03 | 按国家、行政区、城市和关键词组织查询 |
| C04 | 支持服装批发商、零售商、外贸／进口贸易商 |
| C05 | 保存企业基础资料，支持后续查看及导出 |
| C06 | 支持手动和自动触发信息更新 |
| C07 | 从官网及可使用的社交媒体来源补全采购人员和工作邮箱 |
| C08 | 真实搜索与来源记录必须可追溯，不能以模型记忆生成企业名单 |
| C09 | 当前不考虑付费方案，不依赖付费 API、代理、托管采集、联系人服务、在线模型或限时免费额度 |

## 2. 用户问题、证据与验证假设

目标用户为内部销售／外贸业务人员。目前需要逐个搜索企业、打开官网、判断是否为目标企业，再寻找联系人并人工维护表格。

已有对话证据：用户明确需要长期维护的企业名单，并要求澄清样本的发现来源。此前 5 家研究样本经过部分官网核验，但候选来自模型已有知识，不是区域搜索结果，不能用于证明发现模块的覆盖率或正确率。

待验证假设：在同一地区和筛选条件下，工作台可以减少人工整理时间，同时保持可追溯性和企业分类准确度。

验证方式：由同一审核人分别使用人工流程和工作台处理预先定义的同等任务，记录实际耗时、正确企业数、重复数和明确采购入口数。必须包含人工审核时间，不能只比较爬虫运行时间。

建议假设成立条件：完整小样本审核后，每家正确企业的人工处理时间比基线降低至少 30%，且满足第 11 节的资料质量门槛。

建议否定条件：连续两轮优化后仍未达到时间改善，或采购入口始终不足以支持业务使用。采购入口的最低可用比例应在销售品类确定后设定，不虚构统一成功率。

## 4. 核心用户流程

1. 首次启动：选择本地数据目录，查看外部联网说明。
2. 创建任务：选地区、企业类型、关键词、数量限制及是否补全官网。
3. 执行发现：显示当前查询、候选数量、重复数量和阻塞原因。
4. 审核企业：确认地区、官网归属、业务类型以及重复关系。
5. 补全联系人：从已确认官网及可使用的来源查找采购人员和公开工作邮箱。
6. 人工审核：区分采购人员、通用邮箱、其他部门、未找到和未验证。
7. 导出：企业和联系人分别导出，通过企业 ID 关联。
8. 后续更新：执行发现新增或复核已知企业，查看字段变化。

## 5. 功能需求

### FR-01 地区与关键词

- 国家、行政区、城市使用稳定标识，不仅保存显示名称。
- 每个城市显示国家和行政区，防止同名城市混淆。
- 查询范围必须显示“行政边界”或“近似范围”。没有可靠边界时不伪装精确覆盖。
- 内置企业类型词典，允许增删关键词、当地语言别名和排除词。
- 保存实际执行的查询文本、语言和位置上下文。
- 搜索词命中不自动证明企业类型；分类结果与来源证据单独记录。
- 第一版跨国家数据结构就绪，但只承诺已实测的美国地区流程。

### FR-02 企业发现

- Google Maps 发现过程必须是真实执行的查询。
- 每条结果关联任务、查询、地图条目链接或可取得的来源标识、观察时间。
- 在页面实际提供的范围内提取名称、地址、电话、官网和类别。
- 字段缺失时为空并说明原因，不猜测邮箱、网址或公司主体。
- 页面没有明确公司主体信息时，将名称视为商家／展示名称，不冒充工商注册名。
- 支持暂停、恢复、取消、限额终止和已完成子任务续跑。
- 验证码、登录要求、访问拒绝转为“需要人工处理”或“来源不可用”。
- 单次运行结束必须给出结束原因：正常完成、数量上限、时间上限、取消、阻塞或失败。
- “完成”仅表示计划内查询结束，不表示该地区企业全部采集完毕。

### FR-03 企业库与地点

- 企业与经营地点分开：同一企业可以拥有多个门店、总部或仓库。
- 品牌门店不自动认定为独立采购客户；加盟关系不明时保留不确定状态。
- 提供名称、地区、类型、官网、联系人状态、核验时间及跟进状态筛选。
- 支持标记重复、合并及撤销合并。
- 合并保留原始来源、历史字段、联系人及人工备注。
- 来源网站与企业自有官网不能混为一谈；平台店铺域名不能作为企业官网去重依据。

### FR-04 官网身份与业务核验

- 优先使用企业条目提供的官网作为候选入口，核查名称、品牌、电话、地址等对应关系。
- 对域名停放页、目录站、无关重定向和同名公司标记待核实。
- 分类为“批发／零售／制造／进口贸易／其他／无法判断”，允许多标签。
- 官网明确进口业务才能标记进口贸易，不根据“服装批发”推断进口资质。
- 每个分类保留证据页面及简短事实摘要。

### FR-05 采购联系人与工作邮箱

- 优先查找 About、Contact、Team、Buying、Sourcing、Vendors、Supplier 等页面及可读取的公司资料。
- 识别 Buyer、Purchasing、Procurement、Sourcing 等岗位，结合上下文核查。
- 公开人员记录至少包含姓名或部门、职位、来源页面、观察时间。
- 人员与邮箱的对应关系需要明确证据；不能把页面上任意邮箱分配给页面上任意人员。
- 职位身份和邮箱状态分别标注，见第 7 节。
- 当没有个人采购邮箱时，保存采购部门邮箱、供应商申请页或联系表单。
- 销售／客服邮箱作为备用入口，不计为“已找到采购联系人”。
- 第一版不生成姓名拼接邮箱，不通过群发或测试邮件验证地址。
- 不主动收集私人电话号码、私人邮箱等与业务无关的信息。

### FR-06 社交媒体

- 第一版优先记录企业官网链接的官方账号。
- 账号归属不明时标记待核实，不仅凭名称相同确认。
- 可提取允许使用的公开页面中明确展示的采购身份或工作联系方式。
- 每个平台支持程度单独展示：可自动读取、仅人工核验、未支持。
- 不承诺所有社交平台都能自动采集；不把登录墙后批量抓取个人资料作为验收前提。
- 人工补充的信息标记“人工录入”，保留来源及录入时间，不伪装自动采集。

### FR-07 手动及自动更新

- 更新分为“发现新增企业”和“复核既有资料”，可以分别启用。
- 单家企业、筛选集合和原任务均可手动触发更新。
- 定时更新默认关闭，用户启用并选择周期后生效。
- 默认建议每 3 个日历月；界面显示本地时区及下一次运行时间。
- 程序未运行、电脑休眠或断网时不能执行；恢复后同一计划最多补跑一次。
- 没有变化时记录最近检查成功时间；有变化时记录字段、新旧值及来源。
- 请求失败不能清空旧字段。页面没有出现旧邮箱，也不能直接认定邮箱无效或人员离职。
- 自动采集不覆盖人工确认值、跟进备注、拒绝联系标记。
- 发生来源冲突或联系人归属变化时进入待审核。

### FR-08 导出与本地保存

- 企业表一行一家企业；联系人表一行一个联系对象／入口；地点需要时单独导出。
- 稳定 ID 用于关联，不把多个联系人压在同一个不可拆分的字段中。
- 支持中文及原始语言文本，电话、邮编和 ID 保留文本形式。
- 导出包括来源、观察时间、验证状态；默认排除明确拒绝联系的记录。
- 支持查看本地数据库位置、备份和恢复。
- 区分结构化事实记录与原始页面证据，允许按来源配置保存期限。
- 保存到本地不自动代表获得永久使用或再分发权限。

### FR-09 进度与异常

- 展示已计划查询数、已尝试数、完成数、发现条目数、新增企业数、重复数、待审核数。
- 进度根据已知工作量计算；工作量变化时明确标注，不展示虚假的精确覆盖率。
- 错误包含影响范围和下一步：重试、重新核验、人工处理或调整任务。
- 来源结构变化应显式报错，不能以“零结果成功”掩盖解析失败。

### FR-10 AI 的使用边界

- 可用于关键词建议、页面分类、岗位提取和摘要。
- 实体与字段必须来自实际来源或明确标记的人工录入。
- AI 输出须携带对应证据；无法定位证据的值不进入已确认资料。
- 网页中的指令视为网页内容，不得驱动发邮件、执行命令或修改任务。
- 本版不调用在线 AI；未来若引入，需另行明确发送内容及费用。当前不以外发联系人数据作为功能前提。

## 6. 页面设计

| 页面 | 主要内容 | 主要操作 |
|---|---|---|
| 任务中心 | 地区、关键词、状态、进度、下一次运行 | 创建、启动、暂停、恢复、取消、重跑 |
| 企业库 | 企业、地点摘要、分类、联系人情况、核验时间 | 筛选、查看、导出、批量复核 |
| 企业详情 | 基础信息、官网、地点、联系人、证据及历史 | 确认、修正、跟进、单家更新 |
| 待审核 | 重复候选、身份不明、来源冲突、职位邮箱对应不明 | 接受、拒绝、合并、保留旧值 |
| 更新记录 | 新增、变更、检查失败、历史快照 | 对比字段、定位来源 |
| 设置 | 数据目录、备份、来源状态、运行限额、外部服务 | 配置、备份、恢复 |

运行日志与技术错误放在任务详情，不占据客户开发主流程。

## 7. 关键业务状态

### 7.1 企业验证

候选 → 待审核 → 已核实业务／不符合条件。

“已核实业务”只表示来源支持其业务类别，不代表工商核验、采购意愿或信用背书。

### 7.2 联系人状态分离

| 维度 | 允许状态 |
|---|---|
| 人员岗位 | 采购岗位证据明确、其他岗位、部门入口、身份待核实 |
| 邮箱来源 | 官网公开、其他可用公开来源、人工录入、未找到 |
| 邮箱归属 | 与人员对应明确、仅公司／部门入口、对应关系不明 |
| 邮箱技术检查 | 未检查、格式错误、域名邮件配置存在、配置不存在、检查不确定 |
| 联系行为 | 未联系、已联系、已回复、拒绝联系 |

“域名邮件配置存在”不得显示为“该邮箱有效”或“收件人已验证”。

## 8. 数据来源与当前限制

Google Maps Platform 标准条款限制抓取、批量下载及保存内容到服务之外；Places API 的 Place ID 保存例外不覆盖所有商家字段。LinkedIn 用户协议也限制未经授权的自动抓取。[S1][S2][S4]

本次用户选择内部测试并暂缓商业化授权评估，不等同于平台已经授权。本版不实现商业授权管理系统，但必须记录来源、可保存范围、保存期限和权限待评估状态。Google Maps 页面采集可行性与数据使用范围属于上线前未关闭的依赖。

原始网页、照片、评论及完整社交媒体档案不作为客户库的默认保存内容。需要排查解析问题时，短期证据保存由来源配置控制。

## 9. 不做的功能

- 自动发送开发信、社交私信、拨打电话或提交联系表单。
- 承诺采集任意城市全部企业，或承诺采购邮箱覆盖率。
- 绕过验证码、登录限制、付费墙或使用代理池逃避限制。
- 从模型记忆补齐企业或推测个人邮箱。
- 第一版全世界地区及全部语言同时稳定支持。
- 商业化多租户、支付、CRM 双向同步。
- 自动判断企业信用、采购预算或成交概率。

## 10. 交付阶段

| 阶段 | 交付结果 | 放行条件 |
|---|---|---|
| M0 来源验证 | 洛杉矶小规模真实发现试验、限制与失败报告 | 有可追溯真实结果，能识别阻塞；使用范围问题有明确记录 |
| M1 企业工作台 | 任务、企业库、去重、来源、导出 | 发现链路可重复，取消恢复可用，不编造结果 |

四个阶段共同组成内部测试版 v0.1；完成 M1 不得宣称完整需求已交付。
