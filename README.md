# 本地销售线索工作台

本地运行的内部测试工具。数据库初始为空，不附带示例客户，不调用付费 API 或在线模型。

## 启动

首次使用请按以下步骤安装并启动：

```bash
cd /path/to/local-lead-workbench
bash scripts/setup.sh
bash scripts/install_maps.sh  # 需要 Go 1.27.1；下载开源源码及 Chromium
bash scripts/start.sh
```

然后在浏览器打开 `http://127.0.0.1:18765`。保持终端运行，Ctrl+C 同时停止 API 和 worker。

要求 Python 3.11+、Node.js 22.6+；编译 Maps 程序还需要 Go 1.27.1（上游 go.mod 要求）。建议直接安装 Go 1.27.1；如果本机是其他版本，安装器会尝试通过 GOTOOLCHAIN 自动下载 go1.27.1（需要联网），下载失败时会提示处理办法。首轮开发平台 macOS。依赖首次安装需要联网，软件不需要付费服务。

### 体验须知 / 已知限制
- 需要 Python 3.11+、Node.js 22.6+、Go 1.27.1；目前只在 macOS 上验证过。
- Maps 结果会混入少量施工商和邻近城市的企业，需要人工筛选。
- 官网扫描较慢，常以“部分完成”结束；已得到的证据会保留。
- 社媒功能需另外运行 `bash scripts/install_social.sh` 安装，本轮体验未验证。
- 恢复备份时，如果有排队或运行中的任务，恢复会被拒绝；请先等待任务完成或取消/暂停相关任务。

可通过 `LEAD_DATA_DIR` 指定数据目录、`LEAD_PORT` 修改端口。默认数据保存在项目 `data/`，不会加入 Git。

只运行界面/API、不执行后台任务：

```bash
bash scripts/start.sh --api-only
```

## 操作流程

1. 创建目标市场：国家、州／城市、目标企业类型和可选关键词，不填写企业数量上限。填写关键词时只按关键词检索（企业类型只用于命名和筛选）；不填关键词时，按所选企业类型使用服装行业默认检索词（如 clothing wholesaler）。
2. 点击更新市场。系统规划城市分区和检索词查询，先发现企业，再复核官网；来源不可用时显示实际阻塞。地图采集程序异常（如地图页面被意外关闭）会显示为“采集程序异常”并按查询自动重试，与“没有找到结果”分开显示。
3. 可独立手动添加已知企业官网，进入详情并执行官网复核。手动录入标记不会变成自动发现。
4. 在企业详情查看来源、联系人、公开邮箱与字段历史。
5. 在待审核页处理联系人和字段冲突。人工编辑由修订号保护，不被采集覆盖。
6. 导出 CSV 或 XLSX；拒绝联系记录默认排除。XLSX 包含企业、联系人、地点及来源表。
7. 在任务或企业上启用按日历月的计划；应用运行时执行，到期错过后最多补跑一次。
8. 设置页可创建和恢复备份。恢复会替换当前业务数据，恢复前会自动备份当前数据。有排队中或运行中的任务时不能恢复（已暂停的任务不阻止恢复，会被备份内容覆盖）；后台 worker 空闲时可直接恢复，无需停止程序。

## Maps 来源

使用独立的 gosom 开源程序，通过 `scripts/install_maps.sh` 安装。可用 `MAPS_SCRAPER_BIN` 指定本地可执行文件；最终安装方法和实测结果见 [Maps 验证报告](docs/maps-validation.md)。

查询包含城市、州、国家文字上下文。当前不是行政边界全量检索，位置与业务类型须审核。程序安装成功不表示网络和来源一直可用。

## 本版已实现与范围

- 本地 React 界面和 FastAPI。
- SQLite 持久化任务、来源、企业、联系人、变化及计划。
- 同源令牌保护；公开地址范围的官网请求和重定向检查。
- 静态官网的人员区块、部门邮箱、通用邮箱及供应商入口提取。
- 运行暂停／取消／续跑、进程中断恢复。
- 来源变更审核、人工值保护、拒绝联系排除。
- 手动和日历月定时复核。
- CSV/XLSX 与一致性数据库备份恢复。
- 社媒账号发现、账号基础资料和帖子读取；Facebook、Instagram、X 可使用本机专用登录会话，实际结果取决于会话、网络和平台页面可读性。
- 社媒操作按企业集合、操作类型及执行配置去重；不同操作独立排队，重复提交同一操作复用活动任务。
- 社媒字段缺失时保留此前非空资料及其真实来源时间；不同的旧值可在账号详情中查看。读取失败不会成为新的有效资料。
- 市场和官网任务按工作项轮转，每轮为社媒任务提供一个执行机会；正在执行的单个工作项不会被抢占。

尚未实现完整设计中的全部扩展：

- 动态官网没有受保护的 Playwright 渲染回退，明确提示需要人工核验。
- 社媒读取不保证获得完整资料或全部历史帖子；登录失效、验证和读取失败会记录实际结果。
- 地区选择是少量美国城市加自定义文字，不是全球行政边界数据库。
- 不判断邮箱是否真正可收信、不猜采购邮箱、不发送邮件。
- 人工跨来源合并及撤销尚待完善；现有自动去重使用稳定来源键或保守的复合身份依据，不能按名称或域名单独强行合并。

以上是内部可运行增量，不应当作全球稳定爬虫或完整商用产品。

## 日志与诊断

API、worker 和导出子进程分别把 JSON 行日志写到数据目录的 `logs/`（每份 5 MB，保留 5 份），日志里带请求编号、轮次和工作项编号。界面上的“服务出错”会显示错误编号（`req_…`），可以用它在日志里找到对应记录。设置页“诊断信息”可以导出诊断包：包含最近的日志、版本和脱敏后的配置，不含企业、联系人数据，也不含令牌、密钥和登录信息。

## 存储清理

设置页“存储清理”管理磁盘占用：地图原始结果默认保留 30 天，自动备份保留最近 10 份，导出文件保留 7 天，都可以调整。第一次清理前会列出将删除的文件和大小，确认后才删除，之后由后台 worker 定期自动清理并记录；把策略改得更严格时需要重新确认。手动备份永不自动删除，企业、联系人等数据库记录不受影响。只运行 API（`--api-only`）时不会自动清理。

## 测试与开发

```bash
.venv/bin/python -m pytest -q
cd frontend
npm ci
npm test
npm run build
```

`tests/test_maps_stability_review.py` 中有 5 个补丁测试需要 `vendor/` 下的 Maps 源码 checkout；没有运行过 `bash scripts/install_maps.sh` 时它们会显示为 skipped（原因写明需先运行该脚本），安装后会正常执行。

所有合成企业数据仅在临时测试数据库中使用。独立 M0 预检放 `data/m0/`；通过界面启动的真实查询及证据放 `data/runs/`，正常采集结果进入客户库。

官网采集默认使用直接公开网络连接，不继承环境代理。无法连接时会记录实际错误。地图来源受其可访问性与使用条件限制，内部测试不代表已获得数据永久保存或商业使用许可。

## 本机实测（2026-09-22）

Maps 查询实际保存 5 家候选，其中 4 家有官网。另人工录入试点企业A 的已知官网人员页，测试官网提取：保存了两名明确标为 Buyer 的人员及公开工作邮箱，均待人工审核，没有发送邮件。页面邮箱的大小写变体目前分别保存，不能把联系入口条数当作独立人数。该次官网扫描因部分页面超过大小和总时限而为“部分完成”，已得到的证据保留，没有将整站标为核验成功。详情见 docs/live-validation.md。

## 官网扫描策略

优先读取联系、关于、团队、采购和供应商合作页面；新发现的此类页面会优先于队列中的普通页面。商品分类、商品详情、购物车、结账、登录和配送/隐私等政策路径按规则跳过，不占正常页面扫描额度，也不单独导致“部分完成”。来源页面的真实读取失败仍会保留。

运行记录显示本次读取页数、提取联系记录数及规则跳过的页面数；这些是本次扫描统计，不是新增人数。详细错误日志默认折叠，已有历史日志同样显示中文原因摘要。单页大小、时间、页面数量、robots 及跨站检查继续生效。

## 目标市场与逐轮更新

市场库长期累积企业，重复运行只更新已有企业，不重复建档。城市相同但筛选条件不同的市场可共享企业主记录，同时分别保存市场归属。企业仍需核验其业务和地理归属。

- 本轮新增：本轮首次进入该市场，不一定是整个数据库首次收录。
- 存量：该市场之前已有，本轮再次发现。
- 资料变化：本轮观察到信息变化的企业，可能与以上分组重叠；人工修正继续保留并提示来源冲突。
- 本轮未再次找到：历史企业未出现在本轮已执行查询中，仍保留；不表示停业或不再符合条件。

列表支持市场筛选、分类与分页。导出沿用这些条件，导出全部匹配记录而非当前页。相同市场定义再次创建会复用已有市场。

城市范围定位采用 Nominatim 的城市级查询，成功结果缓存；不通过此服务抓企业或做网格反向查询。公共服务按机器串行、至少间隔15秒请求，失败短期缓存；端点可配置。使用条件见 https://operations.osmfoundation.org/policies/nominatim/ 。城市参考数据 © OpenStreetMap contributors，ODbL。区域仅为城市参考包围框，非精确行政边界。

Maps 搜索按关键词及区域拆分，密集结果进一步细分。单个查询的时间和资源预算仍受控，未完成区域会明确记录，可暂停/继续或在后续市场更新中复核。市场没有企业总数截断；“本轮计划完成”只说明本轮查询单元已执行，不保证公开平台展示了城市全部企业。
